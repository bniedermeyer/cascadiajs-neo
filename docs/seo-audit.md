# SEO parity audit — cascadiajs-neo vs legacy (cascadiajs.com)

Audited 2026-10-02 on branch `seo-improvements` (HEAD d9d51db). Every item was verified three ways:

1. built output (`astro build`) vs the live site https://cascadiajs.com,
2. the legacy source in `reference/cascadiajs/` (submodule @ 6acbf63, v6.0.161) — `Legacy src:` lines,
3. TypeSafe (Jev) judgments: `real` = P(genuine problem), `sev` = 0–4 impact score. Items with real < 0.5 were dropped.

Scope: **problems only** (parity regressions with legacy). Improvements beyond parity were removed at the
maintainer's request. Maintainer decisions from the 2026-10-02 grilling session are recorded in each item and
summarised under "Decisions" at the end.

## How to use this doc (for the coding session)

- Work top to bottom; items are independent unless noted. IDs are stable — reference them in commits.
- Respect CLAUDE.md: Astro only, pnpm, never edit `reference/`, URL/visual parity with legacy is the bar.
  Copying assets _out of_ `reference/cascadiajs/public/` into this repo is fine.
- Verify by building into a temp dir: `pnpm exec astro build --outDir /tmp/seo-dist`, then run the
  item's **Check** command against it.
- Intentional pre-launch settings (`noindex` meta, `robots.txt Disallow: /`) are NOT bugs; see Launch checklist.
- Legacy's meta tags all come from `reference/cascadiajs/app/head.mjs`, fed by a `sharing` object set in each
  `app/api/**` handler (`sharingTitle`, `sharingDescription`, `sharingImage`). Defaults in head.mjs:9-13.

### P2 — Share images: relative URL to a missing file on every page

`real 0.90 · sev 2.95`

- **Now:** all 66 pages emit `og:image`/`twitter:image` = `/images/2026/social/social-sharing-general.png`:
  a relative URL, and the file is not in `public/`, `src/assets/` or `dist/`. Default at
  `src/layouts/Layout.astro:18` and `src/shared/data/events/2026.config.ts:10`; no page passes `ogImage`.
- **Legacy src:** `head.mjs:63-66` always emits `baseUrl + image` (absolute). Talk pages use the speaker card
  (`app/api/2026/talks/$slug.mjs`); markdown pages use `'/_public/images/sharing' + path + '.png'`
  (`app/api/$$.mjs:37`, generated by `scripts/create-social-sharing-images.mjs`).
- **Legacy reality (live-checked):** only 29/66 legacy og images load. The 37 others — every `/2026` markdown
  page, all 8 sponsors, 6 talks — return HTTP 500 because legacy never generated them. All 29 working images
  exist un-hashed in `reference/cascadiajs/public/images/` (the `-<hash>` suffix on live is a build fingerprint).
- **Fix:**
  1. Copy into `public/images/2026/share/`, unoptimized (decided; flat folder, keep the un-hashed file names):
     `reference/cascadiajs/public/images/2026/social/*.png` (general + speaker cards) and
     `reference/cascadiajs/public/images/sharing/{code-of-conduct,mailing-list,mailing-list-thanks,unsubscribed,welcome}.png`.
  2. `Layout.astro`: make the image absolute — `new URL(ogImage, Astro.site ?? Astro.url.origin).href`.
  3. Talk pages (`src/pages/2026/talks/[slug].astro`): pass `ogImage=/images/2026/share/speaker-<speaker-slug>.png` (legacy `app/api/2026/talks/$slug.mjs:71` used `talk.speaker.slug`; the new person schema has no slug, so slugify `speaker.name`, e.g. "Filip Sodić" → `filip-sodic`, "Jeff Otaño" → `jeff-otano`)
     when that file exists, else fall back to the general image. Missing speaker cards: kaelig-deloumeau-prigent,
     luis-montes, erik-hanchett, james-ide, michael-liendo, nyah-macklin.
  4. Top-level markdown pages (code-of-conduct, mailing-list, mailing-list-thanks, unsubscribed, welcome): pass their
     sharing image (e.g. add an optional `ogImage` field to the schema in `src/content.config.ts`).
  5. Everything else: keep the general image. That's an improvement on legacy's broken 500s; don't try to
     download those URLs (decided, Q10).
     See Appendix A for the per-page mapping.
- **Check:** `grep -o 'property="og:image" content="[^"]*"' /tmp/seo-dist/2026/talks/teaching-llms-new-tricks/index.html`
  → `https://cascadiajs.com/images/2026/share/speaker-marty-nelson.png`, and that file exists in `/tmp/seo-dist`.

### P3 — Canonical URLs end in `/`, but legacy URLs and internal links don't

`real 0.86 · sev 2.83 · regression`

- **Now:** `Layout.astro` builds canonical from `Astro.url.pathname` → `https://cascadiajs.com/2026/attend/`.
  `astro.config.mjs` doesn't set `trailingSlash`. 57/59 internal links use the no-slash form.
- **Legacy:** no canonical tag (head.mjs). Live `/2026/attend` → 200, `/2026/attend/` → **404**, so every
  non-index canonical currently points at a 404.
- **Fix (decided):** add `trailingSlash: "never"` to `astro.config.mjs`. Nothing else: leave `build.format` at its
  default. Verified with a scratch build: canonicals become `https://cascadiajs.com/2026/attend` and
  `https://cascadiajs.com/2026` (root stays `https://cascadiajs.com/`), and output files are unchanged.
  If Playwright tests in `tests/` request slashed URLs, update the tests rather than the config.
- **Check:** `grep -o 'rel="canonical" href="[^"]*"' /tmp/seo-dist/2026/attend/index.html` → `https://cascadiajs.com/2026/attend`.

### P8 — Workshops have no talk pages; their Speakers-grid cards link back to /2026/

`real 0.83 · sev 2.95 · regression`

- **Where:** the Speakers grid on `/2026` (`src/pages/2026/index.astro:162-163`, `<TalkCard talk={talk} href={talkHref(talk)} />`).
  Four Speakers give Workshops (talks with `type: "workshop"` in `src/shared/data/2026/talks.json`): Ojus Save,
  Engin Diri, Michael Daigler, Amanda Martin. See **Workshop** in `CONTEXT.md`.
- **Now:** `src/pages/2026/talks/[slug].astro` `getStaticPaths` filters out workshops, and `talkHref()`
  (`src/pages/2026/index.astro:28-32`) sends them to `"/2026/"`, so those four cards reload the page.
- **Legacy src:** `app/api/2026/talks/$slug.mjs:43-46` serves every Talk, workshops included, through the same talk page
  (`app/pages/2026/talks/$slug.mjs`). Live 200 for `/2026/talks/{offloading-work-with-the-workers,
deploying-ai-agents-on-aws-with-pulumi-and-amazon-bedrock-agentcore, build-better-agent-tools-with-apify,
build-a-voice-agent-with-vapi}`. The `/2026` cards link there.
- **Fix (decided):**
  1. Generate talk pages for workshops exactly like any other Talk: drop the workshop filter in `getStaticPaths`.
     They get the same title (P4), share image (P2) and after-body sections (P10) as every talk page.
  2. Drop the workshop branch in `talkHref()` so the cards link to `/2026/talks/<slug>`, as legacy does.
  3. Render talk abstracts as markdown (`marked` is already a dependency). Each workshop abstract ends with
     `[[More info and how to register]](/2026/workshops/<slug>)`, which legacy renders as a link
     (`<a href="/2026/workshops/…">[More info and how to register]</a>`). Today the new talk page prints
     paragraphs as plain text.
  4. Leave the `/2026/workshops/*` pages as they are.
- **Check:** the four `/tmp/seo-dist/2026/talks/<slug>/index.html` files exist and each contains an
  `href="/2026/workshops/…"` link; `/tmp/seo-dist/2026/index.html` no longer links Speaker cards to `/2026/`.
